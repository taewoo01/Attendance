공통 UI

- Status bar: 로고(SVG 인라인) + 상단 네비게이션(9개 페이지 링크) + 알림/캘린더 아이콘 버튼 + 사용자 칩(아바타+이름) — 전 페이지 동일 구조, 960px 이하에서 nav 숨김
- Modal (modal-overlay / modal-card): QR 체크인, 출석 현황 등에서 재사용되는 오버레이 패턴 (.open 클래스 토글 방식, JS는 각 페이지에 인라인 <script>로 중복 구현)
- Button (.btn, .btn-primary, .btn-ghost, .btn-done)
- Card/Row 패턴: bom-row(기능 목록), att-row(출석 리스트) 등 grid 기반 row 컴포넌트가 페이지마다 유사하게 재정의됨
- Console/log 스타일 위젯 (console-window), Footer — 전 페이지 동일 구조

디자인 토큰

- 색상 (모든 파일 :root에 동일하게 하드코딩, 공유 CSS 파일 없음)
  - 배경: --bg #081512, --bg-panel #0b1e19, --bg-raised #0e231d
  - 포인트: --teal #48d9b0(주 강조), --amber #e2a83f, --copper #c98c4f(index만 정의)
  - 텍스트: --silk #e7efec, --silk-dim #86a199, --silk-faint #45594f
  - 라인: --border rgba(231,239,236,0.10)
- 폰트: IBM Plex Sans KR(본문), IBM Plex Mono(라벨/숫자/코드풍 UI) — Google Fonts CDN 링크
- Radius: 4~16px(작은 요소), 999px(pill/뱃지/아바타)
- Breakpoint: 공통 960px(nav 숨김), 페이지별로 560~900px대 보조 breakpoint 다수 (통일된 breakpoint 체계는 아님 — 페이지마다 조금씩 다른 값 사용)
- Shadow/기타: box-shadow로 modal/hero 그래픽에 깊이감, dark theme 고정(라이트 모드 없음)

주요 asset

- playground-logo (1).svg — 어떤 HTML에서도 <img>/<link>로 참조되지 않음. 모든 페이지가 로고를 raw SVG(<svg class="pg-logo">...)로 각자 인라인 삽입하고 있어, 이 파일은 현재 미사용 상태(원본 소스 파일로 보임).
- 별도 이미지(png/jpg)나 아이콘 폰트 없음 — 아이콘은 전부 인라인 <svg> (stroke 기반 line icon).
- 별도 .css 파일 없음 — 모든 스타일이 각 HTML의 <style> 블록에 개별 하드코딩.

페이지별 특이사항

- index.html: 순수 정적 목업 중 유일하게 애니메이션/3D 배터리 그래픽(b3d-*) 등 장식 요소가 많고 파일 크기도 가장 큼(50KB, 962줄).
- 각 페이지가 CSS 변수·statusbar·footer를 매번 새로 복붙한 구조 — 공통 컴포넌트/레이아웃이 파일 단위로 완전히 중복됨(공유 include/컴포넌트 개념 없음).
- 데이터(팀원 이름/출석 등)는 모두 하드코딩된 목업 값.
- 인라인 <script>로 모달 열고 닫기 등 상호작용을 페이지마다 독립 구현(공유 JS 없음).

Next.js 변환 시 주의할 점

1. 컴포넌트 추출 필요: statusbar/nav/footer/modal/button 등이 페이지마다 중복 — components/ 하위 공통 컴포넌트로 분리해야 함(단, 이번 단계에서는 분석만, 실제 리팩터링은 별도 작업 지시 필요).
2. 디자인 토큰 통합: :root 변수가 페이지마다 개별 정의(--copper는 index에만 있음) → Tailwind theme/전역 CSS 변수로 단일화 시 누락된 변수(--copper 등) 처리 방침 결정 필요.
3. 인라인 <script> → React 상태: 모달 토글 등 vanilla JS 로직은 useState/이벤트 핸들러로 전환 필요.
4. breakpoint 불일치: 페이지마다 다른 max-width 값 사용 → Tailwind 표준 breakpoint로 정리할지, 커스텀 breakpoint를 유지할지 결정 필요.
5. playground-logo (1).svg 처리: 현재 미사용 원본 파일. Next.js에서는 public/에 옮겨 <Image>로 참조하거나, 기존처럼 인라인 SVG 컴포넌트로 유지할지 결정 필요(파일명의 공백/괄호는 import 시 정리 필요).
6. Google Fonts 로드 방식: 현재 <link> 태그 직접 삽입 → Next.js next/font/google로 전환 검토.
7. 하드코딩된 목업 데이터: 실제 Supabase 연동 시 컴포넌트 props/서버 데이터로 교체 필요(AGENTS.md 원칙상 mock으로 실제 구현을 우회하지 않아야 함).
8. <style> 내 애니메이션(keyframes) 다수: index.html의 3D 배터리 등은 CSS-in-<style> 그대로 유지 가능하나, Tailwind 전환 시 커스텀 CSS로 남겨둘 부분과 utility화할 부분 구분 필요.

코드 수정/파일 생성 없이 확인만 완료했다. 다음 단계(컴포넌트 분리, Next.js 초기화 등) 진행 여부는 지시를 기다리겠다.
